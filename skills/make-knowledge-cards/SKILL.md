# 知识卡片生成

## 输入处理

- **粘贴文本**：直接使用正文，忽略附带的寒暄、指令和格式要求。
- **本地文件**：仅支持 `.md` / `.txt`。读取全文；出现乱码时按 UTF-8 → GBK 顺序重试。
- **其他格式**（PDF、Word、网页链接、图片）：明确说明暂不支持，请用户粘贴正文或另存为 `.md` / `.txt` 后再处理。

## 工作流程

1. **通读全文**，标出候选知识点：定义、机制、因果、数据与标准、步骤、适用条件、常见误区、结论。
2. **排序并合并**：按重要性排序；同义、互相包含、只是换了说法的内容合并成一张卡。
3. **定量**：按知识点计数，不按段落或小标题计数——一段可能含多个知识点，多段也可能只讲一件事。目标 5–8 张；独立知识点不足 5 个就少出，并在开头说明；超过 8 个只保留最重要的 8 个，被舍弃的内容不单独罗列。
4. **逐卡撰写**，严格套用下方模板。
5. **按自检清单逐条核对**，再输出。

## 卡片模板

```markdown
### 卡片 N：<陈述句标题>

- **核心知识**：一句话说清这张卡要记住什么。
- **简明解释**：2–4 句，说清“为什么”或“怎么用”，不重复核心知识。
- **例子 / 自测**：原文有例子就用原文例子（可压缩）；没有就出一道能对照原文作答的自测题。
```

- 可选的 `**原文依据**：` 一行，仅在数字、标准、条件容易被误读时添加，摘录原文关键短句。
- 自测题只出题，不附答案。

## 知识点的切分标准

- 一张卡只回答一个问题。
- 标题写成可判断真假的陈述句，而不是宽泛名词：用“膳食纤维不提供能量”，不用“膳食纤维”。
- 两张卡的标题互换后若内容仍然通顺，说明切分有误，需要重新拆分或合并。
- 解释中出现“另外 / 同时 / 还有”引出第二个独立动作或结论时，说明塞了两个知识点，拆成两张卡。
- 同一对象的同类参数、同一组命令选项可以合成一张清单卡；不同对象或不同用途必须分开。
- 易混概念（如 squash 与 fixup）单独成一张对比卡。
- 教程、流程类文章按步骤顺序排列；其余文章按重要性降序排列。

## 保真规则（不可违反）

- 只使用原文信息，不补充背景、常识、外部数据、反例或延伸结论。
- 数字、单位、比例、前提条件、适用范围原样保留；不四舍五入、不换算、不“约等于”。
- 解释只允许做三件事：把原文说得更通俗、把原文多处事实组合复述、复述原文自己给出的原因。不得补写原文没有的原因、影响、趋势或评价。
- 原文没有说明原因时不要硬补。改为写适用条件、与相邻概念的区别、或这条知识在文中的位置，这些都能由原文支撑。
- 原文有例子时优先使用原文例子；原文没有例子时，自测题的正确答案必须能在原文中找到。同一个例子不要重复用于多张卡。
- 观点、推测、个案经验保留归属（“作者认为”“文章推测”“某案例中”），不与普遍事实混写。全文属于观点文章时，标题写成“作者主张：……”，并在来源行下加一行说明这是作者观点。
- 术语首次出现时用一句白话解释；不引入原文未定义的术语。

## 分类型侧重

- **科普说明文**：优先机制、因果关系、数量边界和常见误区，少收罗列性的背景介绍。
- **教程 / 操作指南**：按步骤排列，每张卡说明为什么这样做或做错的后果，不要退化成命令清单。
- **观点评论**：抓主张、论据和限定条件，分清作者立场与客观事实。
- **新闻资讯**：优先会对读者决策产生影响的变化；同一对象的多个参数合并成一张卡，避免逐条抄数字。
- **清单 / 干货合集**：合并同类条目，删掉只是换了说法的重复项。

## 自检清单

- [ ] 每张卡都能在原文找到依据，必要时已写出原文依据
- [ ] 没有两张卡讲同一件事，也没有一张卡塞了两个知识点
- [ ] 解释里没有原文未提供的因果、影响或评价
- [ ] 数字、单位、条件与原文一致
- [ ] 标题是信息完整的陈述句
- [ ] 解释中没有未加说明的术语
- [ ] 例子或自测题与核心知识一一对应，自测题未附答案，例子未跨卡复用
- [ ] 卡片数为 5–8，或在开头说明了知识点不足的原因

## 输出与保存

- 默认在回复中直接输出 Markdown 卡片，开头一行来源：`> 来源：<文件名 | 用户粘贴文本>`。
- 用户要求保存时，写入源文件同目录：`<源文件名>-知识卡片.md`；粘贴文本则命名为 `知识卡片-<主题>.md`，放在当前项目目录。
- 不在卡片后追加长总结、学习计划或推荐阅读。
